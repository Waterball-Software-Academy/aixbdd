# 功能規格：MES 現場執行

**Plan**: `mes-shop-floor-execution`

**建立時間 (UTC)**: 2026-09-06T09:00:00Z

**狀態**: 草稿

**輸入**: 使用者描述：「現場作業員只按開始／完成，工單依製程定義一站一站自動推進。同一套系統要能承載工序數量、檢驗方式、記錄欄位都不同的兩條線，而不需要為第二條線改程式。本版含跳站阻擋、品檢退回與第 N 次紀錄、合格／重工／報廢分流、報廢超門檻審核、下游開工可用量檢查、管理員自助欄位。」

## 範圍

本版做：工單依製程定義自動推進、終端綁定站點、跳站當下阻擋、品檢退回與第 N 次紀錄、合格／重工／報廢分流、報廢超門檻審核、下游開工可用量檢查、管理員自助新增／調整／停用記錄欄位。

本版不做：排程與派工、產能負載與交期模擬、換線換模時間管理、庫存扣帳與異動、ERP／MRP 介接、成本財務結轉、退貨／退料／退供應商／客訴退回、治具／量測儀／PLC 實體介接、條碼／RFID、設備稼動率／OEE／停機原因、工時／計件／薪資、技能矩陣與認證、離線作業與斷線補傳、報表設計器與自訂匯出格式、多廠區、多語系、行動裝置與平板響應式版面。

管理員自助可做與需供應商協助的邊界見 FR-037。

展示用兩條線：產線 A 金屬前框沖焊線（`MO-FR-27-005`，產品 `FR-27-BZ-A`，10,000 個）；產線 B 監視器整機組裝線（`MO-MON-27-011`，產品 `MON-27-A`，2,000 台）。產線 A 成品是產線 B 第一站的投入料件。

**舉例說明**:

本文件用兩條真實存在上下游關係的產線來說明。目的是證明：**同一套系統可以承載工序數量不同、檢驗方式不同、記錄欄位完全不同的兩條線，而不需要為第二條線改程式。**

產線 A 生產 27 吋監視器用的金屬外框。特徵是工序線性、有中間品檢、不合格會退回重做。

```
薄板沖壓 → 沖壓品檢 → 雷射焊接 → 清洗 → 成品品檢
```

| 工序 | 站點 | 類型 | 作業員 | 是否回報數量 |
| --- | --- | --- | --- | --- |
| 薄板沖壓 | 沖壓線 | 生產 | 王沖壓 | 是 |
| 沖壓品檢 | 沖壓品檢站 | 品檢 | 李檢驗 | 否（回報判定結果） |
| 雷射焊接 | 雷射焊接站 | 生產 | 陳焊接 | 是 |
| 清洗 | 清洗站 | 生產 | 林清洗 | 否 |
| 成品品檢 | 成品品檢站 | 品檢 | 李檢驗 | 否（回報判定結果） |

產線 B 生產 27 吋監視器整機。特徵是投入料件來自產線 A、含機台自動測試、檢驗要拍照存證。

```
前框上料組裝 → 電控模組安裝 → 功能測試 → 外觀檢驗 → 包裝入庫
```

| 工序 | 站點 | 類型 | 作業員 | 特殊性 |
| --- | --- | --- | --- | --- |
| 前框上料組裝 | 組裝一線 | 生產 | 張組裝 | 投入產線 A 的成品 |
| 電控模組安裝 | 組裝二線 | 生產 | 黃組裝 | — |
| 功能測試 | 測試房 | 品檢 | 測試治具 + 周測試 | 機台自動帶入量測值 |
| 外觀檢驗 | 目檢站 | 品檢 | 吳目檢 | 需拍照存證 |
| 包裝入庫 | 包裝線 | 生產 | 蔡包裝 | 完工即入庫 |

產線 A 的 `MO-FR-27-005` 完工入庫後，其成品 `FR-27-BZ-A` 成為產線 B `MO-MON-27-011` 第一站「前框上料組裝」的投入料件。**產線 A 的品檢判定，會直接決定產線 B 能不能開工。**

| 角色 | 誰 | 主要畫面 | 能做什麼 |
| --- | --- | --- | --- |
| 現場作業員 | 王沖壓、陳焊接等 | 工位終端 | 開始 / 完成自己站點的工序，填寫該站欄位 |
| 檢驗員 | 李檢驗、吳目檢 | 工位終端（品檢模式） | 判定合格 / 不合格，分流數量，填不良代碼 |
| 線長 / 班長 | 產線負責人 | 狀態板 + 工單詳情 | 看全線狀態，處理報廢審核 |
| 廠內流程管理員 | 製造部或品保部指定人員 | 系統設定 | 動態新增 / 調整記錄欄位，不需 IT 介入 |

現場有三個畫面：工位終端、牆上狀態板、系統設定。作業員只碰終端；線長看狀態板與待審清單；管理員只進設定。畫面骨架只有一套，差別全部在按下「完成」之後跳出來的表單。

本版明確不做的分類（承諾「這些做、那些不做」才是可交付的）：

| 類別 | 本版不做 |
| --- | --- |
| 流程與排程 | 排程與派工（本版只推進已存在的工單）；產能負載與交期模擬；換線與換模的時間管理 |
| 庫存與帳務 | 庫存的實際扣帳與異動（僅在下游開工時檢查可用量）；ERP／MRP 介接；成本歸集的財務結轉；退貨、退料、退供應商、客訴退回 |
| 設備與介接 | 治具、量測儀、PLC 的實體介接（產線 B 的治具帶值為模擬）；條碼／RFID 掃描；設備稼動率、OEE、停機原因記錄 |
| 人員 | 工時、計件、薪資；技能矩陣與認證管理 |
| 系統面 | 離線作業與斷線補傳（現場網路中斷時的行為本版未定義）；報表設計器與使用者自訂匯出格式（本版提供固定的追溯畫面）；多廠區、多語系；行動裝置與平板的響應式版面（本版針對固定工位終端） |

## 使用者情境與測試 *(必填)*

### 使用者故事 1 - 現場只按開始與完成，工單自動往下一站 (Priority: P1)

作為現場作業員，我希望工位終端已經綁定我的站點、待辦就是這一站該做的那張單，我只按「開始」和「完成」（品檢站按「合格／不合格」），以便工單自己走到下一站，沒有人需要通知、轉派或維護 Excel。

**為何為此優先級**: 沒有這條路，退回、分流、第二條線都無處附著。只實作這一條路即可展示核心價值。

**獨立驗證方式**: 在產線 A 建立 `MO-FR-27-005`，五站依序走完。確認每一站完成後單子自動出現在下一站、狀態板同步、最終品檢合格後工單自動結案；全程不選工單、不輸工號。

**舉例說明**:

王沖壓在沖壓線旁的工位終端，畫面預設就停在「沖壓線」。上半是待辦清單，只有一行：

```
MO-FR-27-005 ｜ 金屬前框 ｜ 薄板沖壓 ｜ 10,000 個 ｜ 可開始
```

下半是工序卡：

```
本關：薄板沖壓
上一關：無
下一關：沖壓品檢
狀態：尚未開始
```

只有一顆可按的按鈕：**開始**。「完成」是灰的。他按「開始」後系統回：

```
本關進行中。作業員：王沖壓。開始：08:12:30
```

工序卡轉「進行中」，「完成」亮起，「開始」變灰。牆上狀態板同步變成：

```
這批現在在薄板沖壓，王沖壓作業中。
```

作業員不需要選工單、不需要輸入工號、不需要記今天要做什麼。系統已經知道這一站現在該做哪一張單。

沖壓完 10,000 個，按「完成」。跳出這一站被設定過的回報表單——不是寫死的固定表單：

| 欄位 | 型別 | 必填 | 這次填的值 |
| --- | --- | --- | --- |
| 實際沖壓數 | 數字 | 是 | 10,000 |
| 模具編號 | 單選 | 是 | MD-FR27-02 |
| 料捲批號 | 文字 | 是 | RC-20260815-A |
| 備註 | 文字 | 否 | （空白） |

送出後系統回：

```
本關已完成。下一關是「沖壓品檢」，由「沖壓品檢站」開始。
```

工序卡變「已完成」，這張單從王沖壓的待辦消失。同一時間，沖壓品檢站的終端上，這張單自動出現，狀態「可開始」。沒有人需要通知李檢驗，也沒有人需要把單子拿過去。

品檢站的工序卡沒有「完成」按鈕，而是**合格 / 不合格**兩顆。李檢驗按「開始」進入判定，抽檢完按「合格」：

| 欄位 | 型別 | 必填 | 這次填的值 |
| --- | --- | --- | --- |
| 抽檢數 | 數字 | 是 | 200 |
| 平面度 (mm) | 數字（上限 0.35） | 是 | 0.21 |
| 判定 | 單選 | 是 | 合格 |
| 合格數 | 數字 | 是 | 10,000 |
| 重工數 | 數字 | 是 | 0 |
| 報廢數 | 數字 | 是 | 0 |

系統回：

```
沖壓品檢合格。下一關是「雷射焊接」。工單尚未結束。
```

雷射焊接（陳焊接）、清洗（林清洗）、成品品檢（李檢驗）依序推進，行為相同。成品品檢按下「合格」後：

```
成品品檢合格。工單已結束。
```

狀態板：

```
五關完成。工單已結束。
```

現場作業員全程只按了「開始 / 完成」，沒有人需要理解系統，也沒有人需要維護 Excel。

**驗收情境**:

1. **Given** 王沖壓在已綁定「沖壓線」的工位終端，待辦顯示 `MO-FR-27-005` 薄板沖壓為「可開始」，「完成」為灰，**When** 他按「開始」，**Then** 本關轉「進行中」、寫入作業員與時間戳、「完成」亮起、「開始」變灰，狀態板顯示這批在薄板沖壓、王沖壓作業中。
2. **Given** 薄板沖壓為「進行中」，**When** 王沖壓按「完成」並送出該站已設定的必填欄位（實際沖壓數、模具編號、料捲批號），**Then** 本關已完成、該單從本站待辦消失，並自動出現在沖壓品檢站、狀態為「可開始」；無人通知、無人轉派。
3. **Given** 沖壓品檢站的工序卡以「合格／不合格」取代「完成」，李檢驗已按「開始」，**When** 他按「合格」並送出必填欄位，**Then** 系統回報下一關是雷射焊接，工單尚未結束；雷射焊接、清洗、成品品檢依序以相同方式推進。
4. **Given** 五站依序完成且成品品檢按「合格」，**When** 判定送出且沒有未結束的重工批，**Then** 工單自動結案，狀態板顯示五關完成、工單已結束。
5. **Given** 工序尚未按「開始」，**When** 作業員嘗試按「完成」，**Then** 「完成」維持不可送出。
6. **Given** 完成表單有必填欄位未填，**When** 作業員送出，**Then** 系統阻擋送出。

**功能需求（FR）**:

- **FR-003**: 系統 MUST 禁止在未按「開始」的情況下按「完成」。
- **FR-007**: 必填欄位未填完時，系統 MUST 阻擋「完成」送出。
- **FR-011**: 工序完成後，系統 MUST 自動將該單推入下一站的待辦清單，MUST NOT 要求任何人工通知、轉派或指定接手人。
- **FR-012**: 工位終端 MUST 綁定單一站點並預設顯示該站待辦；作業員 MUST NOT 需要選擇工單或輸入工號即可操作。

**非功能需求（NFR）**:

- **NFR-001**: 作業員完成一次「開始 → 完成 → 送出」全程的操作步驟 MUST 不超過 3 個主要動作，且過程中不需選擇工單、不需輸入工號。

### 使用者故事 2 - 跳站在按下開始的當下被擋住 (Priority: P1)

作為現場管理者，我希望前置工序未完成時，後段站點按「開始」當場被拒絕、工單狀態完全不變，以便跳站在這套系統裡不存在，而不是事後才被稽核出來。

**為何為此優先級**: 這是證明系統控得住的第一個點；順序來自製程定義，不是寫死在程式裡。

**獨立驗證方式**: 產線 A 沖壓完成、沖壓品檢未做時，在雷射焊接站按「開始」，確認被拒、訊息指名前置工序、資料層無新增紀錄。再以產線 B 做同樣測試，確認被指名的前置工序來自產線 B 自己的製程定義。

**舉例說明**:

沖壓才剛完成，還沒品檢。陳焊接想先把焊接站的機台暖起來，跑到雷射焊接站終端按「開始」。待辦清單上這張單顯示：

```
MO-FR-27-005 ｜ 金屬前框 ｜ 雷射焊接 ｜ 10,000 個 ｜ 還不能開始
```

他按「開始」，系統回：

```
還不能開始。需先完成「沖壓品檢」。
```

工單狀態**完全沒有改變**。沒有任何紀錄被寫進去，狀態板也沒有跳動。

跳站在這套系統裡不是違規，是**不存在的操作**——不是事後稽核發現有人跳站，是當下就按不下去。這個順序不是寫死在程式裡的：產線 B 可以有完全不同的順序、完全不同的站數，因為順序來自製程定義。

**驗收情境**:

1. **Given** `MO-FR-27-005` 薄板沖壓已完成、沖壓品檢尚未完成，陳焊接在雷射焊接站待辦看到該單為「還不能開始」，**When** 他按「開始」，**Then** 系統拒絕並指名需先完成「沖壓品檢」；工單狀態、各站狀態與狀態板與按下之前完全一致，MUST NOT 寫入任何紀錄。
2. **Given** 產線 B 有不同的工序數量與順序，且某後段站的前置尚未完成，**When** 作業員在該後段站按「開始」，**Then** 阻擋行為與產線 A 一致，被指名的前置工序來自產線 B 自己的製程定義。

**功能需求（FR）**:

- **FR-002**: 前置工序未完成時，系統 MUST 拒絕後續工序的「開始」，回應中 MUST 指名需先完成的工序名稱，且工單狀態、各站狀態與狀態板 MUST 保持不變、MUST NOT 寫入任何紀錄。

### 使用者故事 3 - 整批不合格退回重做，舊紀錄以第 N 次保留 (Priority: P1)

作為檢驗員與品保，我希望判定不合格時能指定退回先前的生產工序，被退回的站點回到待辦重做，且每一次執行都留下完整紀錄，以便出事時能在同一頁比對是哪一批料、哪一副模具、哪一個人、哪一個時段。

**為何為此優先級**: 這是客戶買 MES 真正要的追溯；建立在推進骨架之上，但不依賴數量分流。

**獨立驗證方式**: 沖壓品檢整批不合格、退回薄板沖壓；確認後段維持「還不能開始」且從未被解鎖。重做後再檢合格。工單完工後，在同一追溯頁比對第 1 次與第 2 次的模具、平面度與作業員。

**舉例說明**:

李檢驗抽檢發現平面度超標，按「不合格」。表單長出只在不合格時才出現的欄位：

| 欄位 | 型別 | 必填 | 這次填的值 |
| --- | --- | --- | --- |
| 抽檢數 | 數字 | 是 | 200 |
| 平面度 (mm) | 數字（上限 0.35） | 是 | 0.52 |
| 判定 | 單選 | 是 | 不合格 |
| 不良代碼 | 多選 | 不合格時必填 | DEF-FLAT（平面度超標） |
| 合格數 | 數字 | 是 | 0 |
| 重工數 | 數字 | 是 | 10,000 |
| 報廢數 | 數字 | 是 | 0 |
| 退回工序 | 單選 | 是 | 薄板沖壓 |

退回工序的可選範圍僅限本站之前的生產工序（不含品檢站本身）。系統回：

```
判定不合格。工單不能結束。請退回「薄板沖壓」重做。焊接尚未開始。
```

退回瞬間，整條線發生什麼：

| 位置 | 退回前 | 退回後 |
| --- | --- | --- |
| 薄板沖壓 | 已完成 | **可重做**（回到待辦清單） |
| 沖壓品檢 | 進行中 | 不合格 |
| 雷射焊接 | 還不能開始 | 還不能開始（維持鎖住） |
| 清洗 | 還不能開始 | 還不能開始 |
| 成品品檢 | 還不能開始 | 還不能開始 |

狀態板：

```
沖壓品檢不合格，退回薄板沖壓。焊接尚未開始。
```

退回不會刪掉原本的紀錄。王沖壓第一次填的模具編號、料捲批號、實際沖壓數，全部保留。系統記的是「第 1 次沖壓」與「第 2 次沖壓」兩筆，不是覆蓋。後段站點沒有被「解鎖再鎖回去」——它們從頭到尾就沒被解鎖過。

王沖壓換了模具（MD-FR27-05），重做一批，按完成。系統再次把單推到沖壓品檢。李檢驗這次量到 0.19，判定合格。工單完成後，追溯畫面會看到：

```
薄板沖壓      第 1 次   08:12–09:40   王沖壓   模具 MD-FR27-02   料捲 RC-20260815-A
沖壓品檢      第 1 次   09:42–09:55   李檢驗   平面度 0.52   不合格   DEF-FLAT
薄板沖壓      第 2 次   10:05–11:30   王沖壓   模具 MD-FR27-05   料捲 RC-20260815-A

雷射焊接      第 1 次   ...
```

**驗收情境**:

1. **Given** 李檢驗在沖壓品檢已按「開始」，**When** 他按「不合格」並送出（不良代碼必填、退回工序選「薄板沖壓」），**Then** 薄板沖壓轉「可重做」並回待辦、本站轉「不合格」、雷射焊接及之後維持「還不能開始」且從未被解鎖；系統回報工單不能結束。
2. **Given** 判定「不合格」，**When** 未填不良代碼，或退回工序選了本站或本站之後的工序，或選了品檢站，**Then** 系統阻擋送出。退回工序可選範圍 MUST 僅限本站之前的生產工序。
3. **Given** 王沖壓以不同模具重做並完成，**When** 李檢驗第 2 次量到合格平面度並判定合格，**Then** 系統寫入「第 2 次」紀錄，第 1 次的所有欄位值完整保留、未被覆蓋。
4. **Given** 工單已完工，**When** 開啟追溯畫面，**Then** 可在同一頁比對每一站的次數、時段、作業員與欄位值（含兩次沖壓的模具差異、兩次品檢的平面度），切換畫面次數不超過 1 次。
5. **Given** 被退回的來源站已被另一批次佔用為「進行中」，**When** 退回生效，**Then** 退回單進入該站待辦排隊，MUST NOT 立刻開始；目前進行中的批次完成後，排隊中的退回單才可變為可開始。

**功能需求（FR）**:

- **FR-013**: 品檢站判定「不合格」時 MUST 要求指定退回工序，可選範圍 MUST 限於本站之前的生產工序（不含品檢站本身）。
- **FR-014**: 退回時，被退回工序 MUST 轉為「可重做」，後續工序 MUST 維持鎖定。
- **FR-015**: 退回 MUST NOT 覆蓋原紀錄；系統 MUST 以「第 N 次」累加，所有次數的紀錄 MUST 永久保留。
- **FR-016**: 判定不合格時「不良代碼」MUST 為必填。
- **FR-029**: 被退回的來源站已被另一批次佔用為「進行中」時，退回單 MUST 進入該站待辦排隊，MUST NOT 立刻開始；同站同時 MUST 仍只有一張工單處於「進行中」。目前進行中的批次完成後，排隊中的退回單才可變為可開始。

### 使用者故事 4 - 品檢把數量分成合格、重工、報廢三條路 (Priority: P2)

作為檢驗員與製造主管，我希望一次判定能把本批產出分成合格往下走、重工退回前站、報廢就地終止，主批不必等重工批，且下游開工會檢查可用量，以便數量算得準、產能不被重工拖住、跨工單銜接控得住。

**為何為此優先級**: 建立在退回機制之上；證明數量算得準，也證明產線 A 的判定會決定產線 B 能不能開工。

**獨立驗證方式**: 沖壓品檢填合格 9,200、重工 500、報廢 300。確認本站「已完成」、主批可先走、工單不結案。加總不符時 100% 被擋。再以可用量 1,800／需求 2,000 驗證下游第一站被擋。

**舉例說明**:

產出物不可未檢驗就流入下一關：送檢是必經過程，本批全部產出都送檢。因此送檢數等於本批產出數，不是工單計畫數，也不是抽檢數。

沖壓品檢時，李檢驗發現 10,000 個裡面，有一部分邊緣毛邊嚴重、無法重工：

| 欄位 | 值 | 說明 |
| --- | --- | --- |
| 判定 | 部分不合格 | — |
| 合格數 | 9,200 | 直接往下一站走 |
| 重工數 | 500 | 退回薄板沖壓重做 |
| 報廢數 | 300 | 就地報廢 |
| 不良代碼 | DEF-BURR（毛邊） | 報廢與重工共用 |
| 報廢原因 | SCR-UNREPAIRABLE | **報廢數 > 0 時必填** |

系統驗：

```
送檢數 = 本批全部產出數
合格數 + 重工數 + 報廢數 必須等於送檢數（10,000）
```

填不對就送不出去，直接在畫面上標紅。加總正確後，這一站本身已做完判定，看板為「已完成」。一張工單拆成兩條並行推進線：沒過的數量不留在本站，要嘛報廢，要嘛回到先前站點重新排隊。

```
本站（沖壓品檢）          →  已完成
主批  9,200 個            →  雷射焊接  →  清洗  →  成品品檢
重工批  500 個            →  回到薄板沖壓重新排隊（第 2 次）→ 沖壓品檢（第 2 次）→ 併回主批
報廢    300 個            →  結案，不再流動
```

狀態板同時顯示兩行：

```
主批 9,200 個現在可到雷射焊接。
重工批 500 個現在在薄板沖壓，尚未開始。
```

主批在站與站之間不需要等重工批，可以直接往下走。工單不能先結案：主批就算過了成品品檢，只要還有重工批沒結束，工單維持「進行中」。重工批完成品檢後，併回主批當時所在的工序之前。若主批已經跑到清洗，重工批補進來時要從雷射焊接開始追。工單完工數量 = 主批合格數 + 重工批最終合格數，這張單會是 9,200 + 500 = 9,700（假設重工全過），而不是 10,000。報廢的 300 個，成本仍掛在這張工單上。

這件事怎麼影響產線 B。`MO-FR-27-005` 最終只完工 9,700 個前框，產線 B 的 `MO-MON-27-011` 需要 2,000 個。9,700 > 2,000，庫存足夠，產線 B 照常開工。但如果報廢量大到剩下 1,800 個，產線 B 第一站「前框上料組裝」按「開始」會被擋：

```
還不能開始。料件 FR-27-BZ-A 可用量 1,800，需求 2,000，短缺 200。
```

主批過最終品檢後即可計入下游可用量，即使工單因重工批未結束而仍為「進行中」。重工批之後合格的數量再追加進可用量。

**驗收情境**:

1. **Given** 送檢數等於本批全部產出 10,000，李檢驗判定「部分不合格」且合格 9,200、重工 500、報廢 300、報廢原因已填，**When** 判定送出，**Then** 本站看板為「已完成」；主批 9,200 可到雷射焊接；重工批 500 回到薄板沖壓重新排隊（第 2 次）；報廢 300 結案不再流動。狀態板同時顯示主批與重工批。
2. **Given** 合格數 + 重工數 + 報廢數不等於送檢數，或報廢數大於 0 未填報廢原因，**When** 檢驗員送出，**Then** 系統阻擋送出並在畫面標紅；沒有任何加總錯誤或未送檢產出進入下一關。
3. **Given** 主批與重工批並存，**When** 主批繼續往下走而重工批尚未開始，**Then** 主批 MUST NOT 等待重工批；工單維持「進行中」，MUST NOT 結案。
4. **Given** 主批已過成品品檢但重工批尚未結束，**When** 系統檢查結案條件，**Then** 工單維持「進行中」；重工批沿剩餘工序走完，全部結束後才結案。系統 MUST NOT 出現「已結案後再併回重工批」。
5. **Given** 重工批完成品檢，**When** 併回主批，**Then** 起始工序為主批當前工序的前一站。若主批已在清洗，重工批從雷射焊接開始追。
6. **Given** 工單所有重工批已結束，**When** 結案，**Then** 完工數量等於主批合格數加上各重工批最終合格數（例如 9,200 + 500 = 9,700）；報廢數量的成本仍歸該工單。
7. **Given** 上游主批已過最終品檢、可用量 1,800，下游 `MO-MON-27-011` 第一站需求 2,000，**When** 張組裝按「開始」，**Then** 系統阻擋並回應料件代碼、可用量 1,800、需求 2,000、短缺 200。主批過最終品檢即可計入可用量，不必等上游工單結案；重工批之後合格的數量再追加。
8. **Given** 重工批第 3 次及以上判定不合格，**When** 檢驗員指定退回工序，**Then** 系統仍允許退回，MUST NOT 因已重工次數自動改為報廢。檢驗員仍可主動把數量分到報廢。

**功能需求（FR）**:

- **FR-017**: 產出物 MUST 全部送檢，送檢數 MUST 等於本批全部產出數。品檢判定 MUST 做數量分流且 MUST 驗證「合格數 + 重工數 + 報廢數 = 送檢數」，不相等時 MUST 阻擋送出並在畫面標示錯誤。
- **FR-018**: 報廢數大於 0 時「報廢原因」MUST 為必填。
- **FR-021**: 報廢數量的成本 MUST 仍歸屬於該工單，MUST NOT 從帳上消失。
- **FR-022**: 重工批與主批 MUST 獨立推進；主批在站與站之間 MUST NOT 等待重工批。工單結案不在此列，見 FR-010、FR-023。
- **FR-023**: 重工批完成品檢後 MUST 併回主批，起始工序為主批當前工序的前一站。若主批已通過最終品檢但工單尚未結案，重工批 MUST 沿剩餘工序繼續推進；工單 MUST 等到所有重工批結束後才結案。系統 MUST NOT 出現「工單已結案後再併回重工批」的狀態。
- **FR-024**: 工單完工數量 MUST 等於主批合格數加上各重工批最終合格數。
- **FR-026**: 下游工單的第一站在投入料件可用量不足時 MUST 阻擋「開始」，並回應可用量、需求量與短缺量。上游主批通過最終品檢後，該主批數量 MUST 立即計入可用量，即使上游工單因重工批未結束而尚未結案。
- **FR-027**: 本版 MUST NOT 設重工次數上限。重工批判定不合格時，系統 MUST NOT 因已重工次數而自動改為報廢；每次不合格 MUST 仍允許指定退回工序（FR-013）。檢驗員仍可主動把數量分到報廢。
- **FR-028**: 「部分不合格」是判定值，不是獨立看板狀態。判定送出後本站 MUST 轉為「已完成」。未隨合格數往下走的數量 MUST 只走報廢或退回先前站點重新排隊，MUST NOT 留在本站。

### 使用者故事 5 - 報廢超過門檻須線長核准 (Priority: P2)

作為線長，我希望報廢佔比超過管理員設定的門檻時，工單進入待審而不是直接結案，我能在待審清單看到完整追溯再核准或駁回，以便大額報廢有人簽字。

**為何為此優先級**: 財務與品保會問，但不擋現場主路徑跑通。

**獨立驗證方式**: 成品品檢整單報廢 9,700，確認進入待審、工單暫停於成品品檢。線長核准則結案（完工 0）；駁回則退回重新判定。把門檻從 5% 調成 10% 後，佔比 7% 不觸發審核。

**舉例說明**:

報廢是有金額的。低於門檻由檢驗員當場決定，超過門檻必須有人簽字——門檻是廠內管理員可以設定的數字，不是寫死的。

成品品檢時發現整批鍍層附著力不合格，全數無法出貨。檢驗員填：

| 欄位 | 值 |
| --- | --- |
| 判定 | 不合格 |
| 合格數 | 0 |
| 重工數 | 0 |
| 報廢數 | 9,700 |
| 不良代碼 | DEF-COATING |
| 報廢原因 | SCR-UNREPAIRABLE |

最終品檢判定不合格、重工數為 0、報廢數等於送檢數，視為整單報廢，一律走超門檻審核。這一次不是直接結案：

```
報廢數 9,700 已超過本工單允收上限（5%）。
已送出報廢審核，待「線長」核准後生效。工單暫停於「成品品檢」。
```

線長待審清單出現一筆，點進去看得到完整追溯（誰做的、哪副模具、哪批料、每一站的量測值）。核准後：

```
報廢審核已核准。工單 MO-FR-27-005 結案，完工數量 0，報廢 9,700。
```

駁回時：

```
報廢審核已駁回。理由：建議先送重工評估。
工單退回「成品品檢」，請重新判定。
```

工單回到李檢驗手上。管理員若把門檻由 5% 調成 10%，之後報廢佔比 7% 的判定不觸發審核，直接生效。

**驗收情境**:

1. **Given** 報廢佔比（報廢數 ÷ 本次送檢數）超過設定門檻（預設 5%），或最終品檢不合格且重工數為 0、報廢數等於送檢數（整單報廢），**When** 檢驗員送出判定，**Then** 工單進入待審、暫停於當前工序，MUST NOT 直接結案。佔比分母 MUST 為本次送檢數；同一工單多次報廢 MUST NOT 累計。
2. **Given** 線長待審清單出現該筆，**When** 線長點進去，**Then** 看得到完整追溯（誰做的、哪副模具、哪批料、每一站的量測值）。
3. **Given** 線長核准報廢審核，**When** 核准生效，**Then** 報廢生效、工單結案（例如完工數量 0、報廢 9,700）。
4. **Given** 線長駁回並填理由，**When** 駁回送出，**Then** 工單退回該品檢工序，檢驗員重新判定。
5. **Given** 管理員把門檻由 5% 調成 10%，**When** 之後一筆報廢佔比 7% 的判定送出，**Then** 不觸發審核，直接生效。

**功能需求（FR）**:

- **FR-019**: 報廢佔比超過設定門檻（預設 5%）時 MUST 觸發主管審核，工單 MUST 暫停於當前工序。佔比分母 MUST 為本次送檢數；同一工單多次報廢 MUST NOT 累計計算。
- **FR-020**: 審核核准後報廢 MUST 生效；審核駁回時工單 MUST 退回該品檢工序重新判定。
- **FR-025**: 最終品檢判定不合格且重工數為 0、報廢數等於送檢數者 MUST 視為整單報廢，一律走 FR-019 的審核。

### 使用者故事 6 - 第二條產線用同一套畫面、不同的表單 (Priority: P2)

作為要證明系統沒有為單一產線寫死的製造窗口，我希望產線 B 的終端畫面骨架與產線 A 相同，只有按下「完成」之後跳出的欄位不同，以便同一套系統承載工序數量、檢驗方式、記錄欄位都不同的兩條線，而不需要為第二條線改畫面程式。

**為何為此優先級**: 證明「同一套系統」；依賴欄位資料模型已存在，不需要管理介面。產線 A 與產線 B 可同時推進且互不影響。

**獨立驗證方式**: 只建立產線 B 的製程定義與欄位設定，不修改既有畫面與操作流程程式，走完五站。確認表單內容與產線 A 皆不同；功能測試可由治具模擬帶值；外觀檢驗不合格時缺陷代碼與照片必填。

**舉例說明**:

張組裝在組裝一線的終端，看到的畫面結構跟王沖壓在沖壓線看到的**完全一樣**：待辦清單、工序卡、開始 / 完成按鈕。他不需要重新學。差別全部在按下「完成」之後跳出來的表單。

前框上料組裝站：

| 欄位 | 型別 | 必填 |
| --- | --- | --- |
| 完成台數 | 數字 | 是 |
| 前框批號 | 單選（自動帶入可用批號） | 是 |
| 面板批號 | 文字 | 是 |

功能測試站（機台自動帶值，本版以模擬呈現）：

| 欄位 | 型別 | 必填 | 來源 |
| --- | --- | --- | --- |
| 測試報告編號 | 文字 | 是 | 治具自動寫入 |
| 亮度 (cd/m²) | 數字（350–450） | 是 | 治具自動寫入 |
| 色差 ΔE | 數字（上限 3.0） | 是 | 治具自動寫入 |
| 判定 | 單選 | 是 | 治具自動寫入，人可覆寫 |

周測試在這一站幾乎不用打字。治具測完把值送進系統，他只需要確認送出。若治具值超出範圍（例如亮度 480 超出 350–450），判定自動帶「不合格」；他要覆寫成合格必須填理由，未填不得送出。

外觀檢驗站（需拍照）：

| 欄位 | 型別 | 必填 |
| --- | --- | --- |
| 判定 | 單選 | 是 |
| 缺陷代碼 | 多選 | 不合格時必填 |
| 缺陷照片 | 照片（可多張） | 不合格時必填 |
| 合格數 / 重工數 / 報廢數 | 數字 | 是 |

吳目檢用終端上的相機直接拍，照片跟這一次的檢驗紀錄綁在一起。

產線 A 記的是模具、料捲、平面度。產線 B 記的是治具報告、亮度、色差、照片。兩條線用的是同一份畫面骨架。差別全部來自設定。

**驗收情境**:

1. **Given** 產線 B 已有製程定義與欄位設定，**When** 張組裝在組裝一線終端操作，**Then** 待辦清單、工序卡、開始／完成按鈕的版面與產線 A 完全一致，僅站名與工序名不同。
2. **Given** 功能測試站治具模擬寫入亮度 480（有效範圍 350–450），判定自動帶「不合格」，**When** 周測試要覆寫成合格，**Then** 必須填理由，未填不得送出。治具帶值在本版以模擬呈現。
3. **Given** 外觀檢驗判定不合格，**When** 吳目檢送出，**Then** 缺陷代碼與缺陷照片皆必填；照片與該次檢驗紀錄綁定。

### 使用者故事 7 - 廠內管理員自助新增、調整、停用記錄欄位 (Priority: P3)

作為廠內流程管理員，我希望能在系統設定裡新增、調整、停用記錄欄位並立刻生效，不必重新部署，以便現場從下週開始就能記錄新欄位，且已經發生過的事實不會被改寫。

**為何為此優先級**: 管理端能力，不影響現場流程能否跑通。

**獨立驗證方式**: 管理員為雷射焊接新增「氬氣流量」數字欄位（必填、範圍 12～20）並儲存。計時不超過 3 分鐘、不重新部署、不停機。下一秒該站完成表單出現新欄位；舊紀錄顯示「—」且不被追認為缺漏。

**舉例說明**:

品保部要求：從下週起，雷射焊接站要記錄氬氣流量。廠內流程管理員登入系統設定 → 記錄欄位 → 選擇「雷射焊接」→ 新增欄位：

| --- | --- |
| 欄位代碼 | `argon_flow` |
| 顯示名稱 | 氬氣流量 (L/min) |
| 資料型別 | 數字 |
| 是否必填 | 是 |
| 適用工序 | 雷射焊接 |
| 有效範圍 | 12 ~ 20 |

按儲存。全程約三分鐘，沒有開需求單，沒有重新部署，沒有系統停機。下一秒，陳焊接在雷射焊接站按「完成」，表單多出一格：

```
氬氣流量 (L/min)  [        ]  必填
```

沒填不能送出。填 25 會被擋：

```

```

對既有資料的影響：

| 情況 | 系統行為 |
| --- | --- |
| 新欄位設定前已完成的工序紀錄 | 不受影響，該欄位顯示「—」。不會被追認為缺漏。 |

| 屬性 | 說明 | 範例 |

**驗收情境**:

1. **Given** 廠內流程管理員進入系統設定 → 記錄欄位 → 選擇「雷射焊接」，**When** 他填欄位代碼、顯示名稱、資料型別、是否必填、適用工序、有效範圍並儲存，**Then** 全程不需重新部署或系統停機；下一秒陳焊接按「完成」時表單多出該欄。

4. **Given** 設定當下有工序已開始、尚未按「完成」，**When** 作業員按「完成」，**Then** 表單套用當時最新的欄位版本（含新必填欄位）。工序紀錄綁定的是完成送出那一刻的欄位版本。

6. **Given** 欄位代碼已建立，**When** 管理員嘗試修改欄位代碼，**Then** 系統拒絕。顯示名稱可隨時改，且 MUST NOT 影響歷史資料。

- **FR-030**: 記錄欄位 MUST 由六個屬性定義：欄位代碼、顯示名稱、資料型別、是否必填、適用工序、驗證範圍。

### 邊界情況

- 當後段站點在前置未完成時被按「開始」，系統 MUST 當場拒絕，工單狀態、各站狀態與狀態板完全不變，資料層無新增紀錄。
- 當整批不合格退回時，後段站點 MUST 維持「還不能開始」，且 MUST NOT 被「解鎖再鎖回去」。
- 當被退回的來源站正被另一批次佔用為「進行中」時，退回單 MUST 進入待辦排隊，同站同時仍只能有一張「進行中」。
- 當兩個終端幾乎同時對同一站按「開始」時，系統 MUST 只接受第一個成功請求；後到者被拒絕，且回應指出本站已有人開始。
- 當合格數 + 重工數 + 報廢數不等於送檢數時，系統 MUST 在送出前阻擋並標紅。
- 當報廢數大於 0 但未填報廢原因時，系統 MUST 阻擋送出。
- 當報廢佔比超過門檻或整單報廢時，工單 MUST 進入待審而非結案，暫停於當前工序。
- 當線長駁回報廢審核時，工單 MUST 退回該品檢站重新判定。
- 當主批已過最終品檢但重工批尚未結束時，工單 MUST 維持「進行中」；主批數量已計入下游可用量。
- 當下游第一站投入料件可用量不足時，按「開始」MUST 被擋，訊息含可用量、需求量、短缺量。
- 當重工批第 3 次及以上判定不合格時，系統 MUST 仍允許指定退回，MUST NOT 因次數自動改為報廢。
- 當數值欄位超出有效範圍時，系統 MUST 阻擋送出；若該欄位設定為「可覆寫」，覆寫 MUST 要求填寫理由。
- 當新欄位設定前已完成送出的紀錄被查看時，該欄位 MUST 顯示「—」，且 MUST NOT 被追認為缺漏。
- 當進行中的工序在欄位變更後才按「完成」時，MUST 套用完成送出當下的最新欄位版本。
- 當同一站待辦多於一張單時，選單行為未在本版定義（見假設）。

### 關鍵實體 *(若功能涉及資料，必填)*

- **產品**: 被生產的品項；產品代碼、名稱；對應一份製程定義。
- **製程定義**: 一項產品要經過哪些工序、順序為何；工序順序來自此處而非程式（FR-006）。
- **工序**: 製程中的一個環節；名稱、類型（生產／品檢）、所屬站點、是否回報數量。
- **站點**: 現場的實體工作位置；名稱、綁定的工位終端、對應作業員；同時只能有一張工單進行中（FR-004）。
- **工單**: 一次生產任務；工單號、產品、計畫數量、狀態、完工數量；擁有一或多個批次。仍有未結束重工批時不得結案（FR-010、FR-023）。
- **批次**: 工單內獨立推進的數量單元；類型（主批／重工批／報廢批）、數量、當前工序。重工批退回前站重新排隊，與主批獨立推進，但不設重工次數上限（FR-022、FR-027、FR-028）。
- **工序紀錄**: 某批次在某工序的一次執行；次數（第 N 次）、開始／結束時間戳、作業員、欄位值集合、綁定完成送出當下的欄位版本；只增不覆蓋（FR-015、FR-034）。
- **記錄欄位定義**: 某工序要記錄什麼；欄位代碼、顯示名稱、資料型別、是否必填、適用工序、驗證範圍、啟用狀態。
- **欄位版本**: 欄位定義的某一次快照；版本識別、生效時點。工序紀錄綁定完成送出當下的版本（FR-034）。
- **品檢判定**: 一次品檢的結果；判定值（合格／不合格／部分不合格）、送檢數（= 本批全部產出）、抽檢數、合格數、重工數、報廢數、不良代碼、報廢原因、退回工序。部分不合格後本站狀態為已完成（FR-017、FR-028）。
- **不良代碼／報廢原因**: 可設定的代碼清單；代碼、顯示名稱、啟用狀態；由流程管理員維護（FR-037）。
- **報廢審核**: 超門檻報廢的簽核單；關聯工單與品檢判定、送審時點、審核者、結果、駁回理由。
- **使用者／角色**: 操作者及其權限；姓名、角色（作業員／檢驗員／線長／流程管理員）、所屬站點。
- **料件庫存**: 跨工單銜接的可用量；料件代碼、可用量。主批過最終品檢即計入，下游開工前檢查（FR-026）。本版只檢查可用量，不做扣帳。

關係：產品 → 製程定義 → 工序 → 站點；工單 → 批次 → 工序紀錄（綁定欄位版本）；品檢判定 → 報廢審核；料件庫存給下游工單第一站檢查。

#### 狀態模型

**工序狀態**

```
尚未開始 ──開始──▶ 進行中 ──完成/合格──▶ 已完成
                      │
                      ├──部分不合格──▶ 已完成（未過數量以報廢或退回重工離開本站）
                      └──不合格──▶ 不合格 ──▶（前站轉為「可重做」）

尚未開始 ◀──（前站未完成）── 還不能開始
已完成 ──（被後站退回）──▶ 可重做 ──開始──▶ 進行中
```

**站點看板狀態**

| 狀態 | 顯示 | 意義 |
| --- | --- | --- |
| pending | 尚未開始 | 前站未完成，鎖定中 |
| ready | 可開始 | 輪到這一站了 |
| running | 進行中 | 有人正在做 |
| done | 已完成 | 這一站過了；部分不合格後本站也是這個狀態 |
| failed | 不合格 | 整批品檢判退 |
| rework | 可重做 | 被後站退回，等待重做 |

「部分不合格」是判定值，不是第七個看板狀態。

**工單狀態**

```
待生產 ──首站開始──▶ 進行中 ──末站品檢合格且所有重工批已結束──▶ 已結案
                        │
                        ├──仍有重工批未結束──▶ 進行中（主批可已過最終品檢）
                        ├──報廢超門檻──▶ 待審核 ──核准──▶ 已結案（報廢）
                        │                     └──駁回──▶ 進行中
                        └──料件短缺──▶ 暫停（等料）
```

**數量公式**

```
送檢數 = 本批全部產出數
送檢數 = 合格數 + 重工數 + 報廢數
工單完工數 = 主批合格數 + 各重工批最終合格數
```

## 成功標準 *(必填)*

### 可量測成果

- **SC-001**: 作業員完成一次「開始 → 完成 → 送出」全程的操作步驟不超過 3 個主要動作，且過程中不需選擇工單、不需輸入工號。
- **SC-002**: 未經教育訓練的新作業員，首次在工位終端獨立完成一次「開始 + 完成」的成功率達 90% 以上，耗時不超過 60 秒。
- **SC-003**: 跳站操作 100% 在按下按鈕的當下被拒絕；系統上線後由事後稽核發現的跳站紀錄為 0 筆。
- **SC-004**: 任一已完工工單，可在 30 秒內從單一追溯畫面看出每一站的執行次數、作業員、時段、料批、模具與量測值，切換畫面次數不超過 1 次。
- **SC-005**: 品檢分流時送檢數等於本批全部產出；加總不符時，100% 在送出前被擋下並標示出錯的欄位；沒有任何加總錯誤或未送檢產出進入下一關。
- **SC-006**: 報廢佔比（報廢數 ÷ 本次送檢數）超過門檻的工單 100% 進入待審狀態；未經核准而結案的工單為 0 筆；同工單多次報廢不因累計誤觸發。
- **SC-007**: 新增一條工序數量與記錄欄位皆不同的產線並完整走完全流程，所需的畫面與操作流程程式修改為 0；改動僅限製程定義與欄位設定資料。
- **SC-008**: 管理員從進入設定畫面到新欄位出現在現場表單，全程不超過 3 分鐘，且不需重新部署或系統停機。進行中的工序按「完成」時即看得到該新欄位。
- **SC-009**: 欄位設定變更（改名、改必填、停用）後，變更前已完成送出的工序紀錄顯示內容 100% 不變。
- **SC-010**: 退回重做的工單，其前次執行的所有欄位值 100% 可查；因退回而遺失的紀錄為 0 筆。
- **SC-011**: 主批已通過最終品檢但重工批尚未結束時，工單結案筆數為 0；所有重工批結束後才結案。系統上不得出現「已結案工單又併回重工批」。
- **SC-012**: 重工批第 3 次及以上判定不合格時，系統仍允許指定退回；不得因次數自動改為報廢。

## 假設

- 工位終端為固定綁定單一站點的觸控裝置，一台終端只服務一個站點。
- 作業員身分由終端的登入狀態決定，不在每次操作時輸入工號。
- 整關做完才轉下一站，不支援生產中途先轉出部分數量。
- 同一站的待辦清單通常只有一張單；多於一張時的選單行為未定義。
- 本版為純前端原型，資料存於瀏覽器端，無後端、無資料庫、無 ERP 介接。
- 網路持續連線；斷線期間的行為不在本版範圍。現場網路中斷時的行為本版未定義。
- 產線 B 功能測試的「治具自動帶值」在本版以模擬方式呈現，非真實設備介接。
- 產線 A 與產線 B 的數字（10,000 個、2,000 台、5% 門檻）為展示用範例值，非客戶實際參數。
- 產出物不可未檢驗即流入下一關；送檢數等於本批全部產出數，不是工單計畫數，也不是抽檢數。
- 本版不設重工次數上限；若現場反覆判退，工單會一直維持進行中、不得結案。展示時重工次數由示範劇本控制。
- 本版不做庫存扣帳；FR-026 只在下游開工時檢查可用量。
- 報廢成本僅在工單層面標示歸屬，不做財務結轉。
- 本版針對固定工位終端，不包含行動裝置與平板的響應式版面。
- 現場有三個畫面：工位終端、牆上狀態板、系統設定。作業員只碰終端；線長看狀態板與待審清單；管理員只進設定。
