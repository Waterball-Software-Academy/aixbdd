# PM 撰寫規則（好讀優先的 Example 寫法）

草擬與收斂 Example 時的撰寫判準。核心：句子為測試意圖最佳化、值為嚴格度服務，兩者的取捨點是必要參數。

## 總則：兩股拉力，樞紐是必要參數

1. 可讀性——句子服務測試意圖：語句為「這個例子要證明什麼」而最佳化，讓人一眼看出測試意圖。這股力量把例子推向精簡、抽象。
2. 精準的值——Spec by Example 原則：在該測試意圖上直接寫出要測試的資料實際值。Gherkin 裡沒有「值」，就無法判斷測試的嚴格程度（例如邊界值分析是否成立）。這股力量把例子推向具體。

取捨點是必要參數：先想這個情境在乎的參數是什麼，才反推語句的表達。在乎的參數＝必要參數，必須以具體值出現在例子裡；不在乎的參數＝非必要參數，不入句、不入表，交給下游預設值。必要／非必要之分直接決定抽象顆粒度。

DataTable 分工：Given 用表盤點資料是必要的；When／Then 以句子表達測試意圖為主，只有必要參數多到需逐項核對時才抽表。When／Then 充滿表格會淹沒測試意圖。

檢核標準是「人看得懂」：把句子唸出來，像一句正常人講的話、且看得出這個例子在測什麼，才算過。

## 承諾與證據

1. 標題是承諾、例子是證據：Rule 承諾「該使用者的」「區間內的」這類過濾語意時，例子必須有「髒水」當反證——髒水＝故意建立、依規則不應出現在結果中的資料；過濾失效髒水就漏進結果讓斷言紅燈。自查：想像一個無視標題關鍵字的爛實作，這個例子擋得住嗎？擋不住就把承諾改小或補髒水。
2. 排除型驗證明文寫「不包含」：驗「X 不出現在結果中」必須建立 X 並在 Then 明文寫不包含 X；只驗「共 N 筆」是代理斷言。例外：預期筆數為零時筆數即可作證。
3. 例子只驗所屬 Rule 的職責：別條 Rule 的區辨性斷言不順手帶驗，紅燈時才分得清壞的是哪個承諾。

## 一致性

1. Example 標題與步驟語意一致：標題說「查指定使用者」步驟卻是「查自己」即打架，拍板後對齊。
2. 用詞一致但語句模板不必一致：同一業務概念全 package 一種寫法（查 `dsl-dictionary.md`，見 `dsl-dictionary.md` 規則）；但不得為了句型模板通用而萃取過多參數——句型服務各自的測試意圖，不同例子在乎的參數不同，句型就可以不同。

## 可核對性

1. Given 給出的資訊必須被 Then 驗證或驅動本例行為，兩者皆非的刪除——出現卻不驗的資訊讓讀者誤以為它影響結果。
   - **driving-only 是合法形態**：某個前置只是被測規則的判斷輸入、本批次刻意不對它下斷言（典型：權威狀態屬別的 milestone，本批次不驗），這仍屬「驅動本例行為」，**不得因為 Then 沒驗就刪掉**——刪掉就換掉了等價類。
   - 但 driving-only **必須留痕**：在 `{feature}.dsl-intent.md` 該 Example 的逐句意圖裡明記兩件事——**為何不斷言**（例：權威狀態屬 M3，本批次不對它下斷言）與**誰負責維護該值**（哪個 milestone／owner 之後要補上斷言）。沒有這段記載，稽核者與下游 dsl-refine 無從分辨「合法的 driving-only」與「漏了斷言」，只能回問。
   - SBE 產出時對判定為 driving-only 的欄位**自動生成**這條 intent 註記，不要等稽核者來問。
2. 衍生狀態要讓讀者手算得出來：算出來的值（如時間推導的狀態）只准出現在 Then，算式的全部輸入（含「現在時間」）要在 Given 備齊；答案不能寫進題目。自查：遮住 Then 只看 Given，算得出狀態嗎？
3. Given 寫不寫的判準是「它是不是被測條件的輸入」：缺席本身是被測條件（如「沒有任何行程」）→ 明寫；與失敗無關 → 不寫。前置（參數）失敗例多建無關資料會污染失敗來源隔離，最小 Given 為美。

## 語言與可讀性

1. 「沒有」用存在語意：寫「沒有帶」「不包含」，不寫「為空」「為 null」——那是資料層值語意，由下游決定斷言方式。例外：「列表沒有內容」是觀察得到的，可用。
2. 測試設計術語不進句子：「閉區間」「邊界值」「等價類」放 `#` 註解記錄設計意圖；標題與步驟講使用者情境。
3. 時間用讀者語言且明示時區：「2026-01-15 09:00（台北時間）」；轉 UTC/ISO 是下游翻譯層的事。
4. 專有名詞用中文引號「」圈起；ASCII 雙引號 "..." 專門表達參數值，兩者不得混用。
5. 句子超過約 20 字加標點分隔子句。
6. 標題與例名是主詞動詞受詞齊備的完整白話句：禁數學術語（昇冪 → 由小到大）與電報式壓縮（不回列、僅回查得者）。查無類假值用「格式正確但不存在」的值（EMP_X99），不用喊話式假值（NO_SUCH_USER）。

## 空情境與失敗

1. 查無資料是正常結果不是錯誤：標題與 Then 都要明文「仍成功」；空前置明寫，不靠「什麼都沒建」讓讀者自己推。
2. 空情境用該回應型態的零值表達：列表 →「沒有內容」；統計聚合 → 零值（0 筆、0 元）。先看 happy 例子的回應形狀再選表達；空情境例子放一筆條件外資料當髒水，同時證明過濾與零值。
3. 失敗例寫出失敗原因（未填、超限、重複、查無），不得只寫「沒有成功」。
